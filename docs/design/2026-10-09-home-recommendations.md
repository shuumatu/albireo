# 首页推荐功能改进说明

实施日期：2026-10-09 至 2026-10-11

范围：展示前端首页首屏下方的「精选影像」「旅途回忆」「热门作品」，以及它们依赖的推荐接口、共享卡片和旅途地图入口。本文记录本轮已经实施的调整、验证结果及其边界。

## 1. 本轮解决的问题

首页下方三个模块原本具备卡片展示和跳转能力，但加载恢复、推荐数据口径、筛选交互以及旅途进入地图后的范围保持还不完整。主要问题并非缺少更多内容模块，而是已有入口在异常、空数据、刷新和窄屏场景下不能清楚表达当前状态。

| 模块 | 原有问题 | 本轮调整 | 用户可以感知的变化 |
| --- | --- | --- | --- |
| 精选影像 | 缺少主动换组和当前结果类型筛选；后端会用最新内容补足精选，削弱精选含义 | 增加换组、图片/视频筛选和数量反馈；接口只返回明确标记为精选的内容 | 可以换一批内容，只查看本组图片或视频；未配置精选时看到可操作的空状态 |
| 旅途回忆 | 日期与地图时间轴比例耦合，同日或很短的旅途范围容易被丢弃；地图相机视口扩大时查询范围也跟着扩大 | 独立保存旅途日期和原始拍摄范围；地图显示范围提示并提供退出入口；统一地图照片和结束日期口径 | 点击旅途后按其日期与拍摄范围浏览；拖动地图不会悄悄变成浏览其它旅途；可点击「浏览全部」退出 |
| 热门作品 | 图片/视频各取部分候选会漏掉某一类型占主导时的真正高分内容；SQL 与 Java 重新计算的热度存在精度和时间差异 | 两种类型各取足够候选，复用 SQL 热度分统一合并排序；增加独立刷新、类型筛选和热门主题搜索入口 | 热门排序更符合实际分数；某一类内容占优势时不再被固定配额提前截断 |
| 共用交互 | 缺少刷新失败保留、封面恢复和完整空态；内容变化后滚动按钮可能过时；移动端互动信息依赖悬停 | 抽出独立请求状态、统一推荐区块和卡片回退；跟踪真实内容宽度；补齐触屏和键盘反馈 | 单个模块失败可以独立重试；刷新失败仍能继续浏览；卡片和滚动操作在窄屏、触屏及键盘下更稳定 |

## 2. 三个模块的加载、刷新和空状态

`useRecommendationFeed` 为每个模块分别维护数据、首次加载、刷新、首次错误和刷新错误。首页同时发起三个请求，各自更新自己的内容；其中一个失败不会把其它两个模块一起替换为错误界面。

首次进入时显示骨架屏。请求失败后，模块内显示错误说明和「重试」按钮。成功返回空数组时，展示对应空状态，不把成功的空响应当成网络失败。

已有内容后的刷新采用保留展示的方式：按钮进入「更新中…」并暂时禁用，原卡片继续可用。刷新成功后替换内容；刷新失败后保留上次成功结果，提示「刷新未成功，仍显示上次加载的内容」。这样网络短暂异常不会让用户正在浏览的内容消失。

每次重新加载会取消该模块上一请求，页面卸载时也会取消请求；已取消的请求不会继续覆盖数据或错误状态。请求拦截器对取消单独返回，不将正常取消记作一般 API 错误。

空状态提供与模块对应的出口：精选和热门可进入时间线，旅途可进入地图。首页还增加三个内容锚点，便于直接定位到精选、旅途或热门区块。

## 3. 精选影像与热门作品

### 3.1 筛选只作用于当前这组结果

两个媒体模块复用 `HomeMediaSection`。各自拥有「全部」「图片」「视频」三个筛选按钮，并显示该类型数量及「本组显示 X / Y 件」。一个模块的筛选不影响另一模块。

这里的筛选是在已经返回的推荐列表内进行，未新增全库按类型查询接口。例如，本组显示「视频 0」不代表整个站点没有视频。切到没有内容的类型后，页面明确提示「本组暂无…」，并提供「查看本组全部」恢复入口。

筛选通过 `aria-pressed` 表达选中状态；数量反馈使用状态提示。图片与视频保留各自详情路由，视频卡片也有明确类型标记。

### 3.2 精选回归明确的业务含义

精选接口只返回 `is_featured=true` 且符合可见性条件的图片和视频。原来不足指定数量时用最新内容补齐的做法已移除；实际只有少量精选时返回实际数量，没有精选时返回空列表。

「换一组」重新请求随机精选结果，不承诺每次都与上一组完全不同。当符合条件的内容数量很少时，重复出现同一作品是正常结果。

### 3.3 热门排序使用同一分数来源

热门继续使用现有业务公式：

```text
热度 = (点赞数 × 3 + 评论数 × 2) / (距发布时间的小时数 + 2)^1.5
```

本轮修正的是候选获取和合并过程。视频和图片分别最多取 `limit` 条，再按 SQL 返回的热度分合并取前 `limit` 条，避免原先每类仅取部分配额时漏掉高分内容。服务端不再用另一套取整后的小时数重算分数；热门查询处于同一只读事务内，让数据库计算使用一致的时间基准。相同分数继续按发布时间、类型和 ID 排序，使结果有确定的次序。

有热门主题且有热门卡片时，首页提供「搜索热门主题」链接，进入现有搜索页并带入主题文字。它是搜索入口，并不把热门卡片列表宣称为该标签下的完整内容列表。

## 4. 旅途回忆与地图入口

### 4.1 旅途目前仍是自动聚合

现有旅途由后端按自然月及经纬度 `0.5° × 0.5°` 网格聚合，至少两件符合条件的内容形成一张卡片。时间使用拍摄时间，缺失时使用创建时间；同时要求内容已处理完成、具有地理位置，并遵守现有可见性规则。图片分支只统计 `type='photo'`，不把生成封面当作独立照片计数。

它仍然是影像的自动分组，不是人工编写的游记，也不代表系统已经识别出真实行程的开始和结束。`0.5°` 是角度网格，尤其经度方向的实际距离会随纬度变化，不能理解为处处固定 50 公里的精确旅行范围。

卡片呈现月份、日期范围、作品数量、封面及地点。地名不可用时显示坐标；坐标数据缺失时使用可读的占位文字。日期展示保留接口给出的日历日期，避免浏览器时区转换让日期跨天。

### 4.2 地图相机与查询范围分开

过去主要通过 `fitBounds` 定位地图，再把旅途时间映射为全局时间轴比例。相机为了适配屏幕纵横比和留白会扩展可视范围，容易带入邻近区域；同日旅途或占全局时间跨度很小的旅途也容易被时间轴最小跨度限制吞掉。

现在，旅途链接中的原始边界与起止日直接作为查询范围保存。相机仍会定位到这一区域，但不会用展开后的相机视口替换旅途原始范围。日期也直接传给接口，不再依赖首次聚合返回后换算时间轴比例。

进入范围浏览后，地图显示「旅途范围」以及日期或范围说明，并提供「浏览全部」按钮。范围模式下隐藏普通时间轴，避免控件状态与实际请求条件不一致；空结果文案也改为「旅途范围内没有内容」，提示使用范围退出入口。退出后移除旅途参数，恢复按当前地图视口浏览。

同一地图页面只修改查询参数时，重新应用范围和请求状态，同时清理旧标记、旧数量与簇详情，避免 Vue Router 复用页面实例时继续显示上一范围的数据。

### 4.3 日期和空间边界处理

旅途参数统一经过 `tripMap` 校验：检查合法日历日期、日期顺序、经纬度范围及数值有效性。允许起止日期相同，也允许边界退化为一个点或一条线，因为多件作品可能在同一天、同一地点拍摄。合法中心点可作为缺少有效边界时的定位回退。

日期查询使用包含结束日的用户语义：控制器把结束日转换为次日零点，SQL 采用左闭右开区间 `[开始日零点, 结束日次日零点)`。这样包含结束日当天内容，又不会额外包含次日零点的数据。地图聚合、计数和簇内列表统一使用该边界及照片类型过滤。

2026-10-11 坐标链路核查确认上传解析和位置 API 均直接使用 WGS84。地图相机、标记和查询因此统一保留原始 WGS84，移除了根据经纬度矩形范围推断 GCJ02 的错误转换。单点、同经度及同纬度的旅途范围仍正常定位。管理后台选点也改为直接保存 WGS84；历史手动地图选点可能混有偏移坐标，不能对所有旧数据统一转换。

高缩放下每类媒体的点模式容量为 500。旅途范围固定后，不能依靠平移来找回被这一上限截掉的内容。现在超过容量时继续使用当前缩放级别的完整网格聚合，保留全量数量和簇内分页入口；每类不超过 500 件时仍展示单个点。

### 4.4 仍不是严格的成员 ID 契约

本轮地图链接传递日期和空间边界，没有传递旅途成员 ID，也没有新增按 `tripId` 查询固定成员集合的接口。因此，「按旅途范围浏览」不等同于「只返回生成该卡片时的那些成员」。

日期已按整日查询，空间使用包围盒；同一日期范围及边界内、符合可见性条件的其它内容也可能被包含。数据或可见性变化也会改变随后返回的结果。缺少边界、仅有中心点的旧链接仍只能定位地图并结合可用日期筛选。文案和验收不应承诺卡片数量与地图查询结果在所有情况下严格相等。

## 5. 卡片、横向浏览和无障碍

媒体卡片支持仅有有效派生图的内容；派生图加载失败时，尝试原封面地址，失败后提供明确占位。刷新返回修复后的封面时，复用卡片实例也会重置之前的失败状态。旅途封面采用相同的恢复思路。

共享推荐区块同时观察轨道、直接子项尺寸和子项增删。当筛选改变内容数量、卡片变宽或加载状态改变时，重新计算左右按钮可用性；按钮通过 `aria-controls` 关联到对应轨道。首页保留连续横向拖动模式，详情页相似内容维持原有吸附模式。

结果组改变时回到首张，并停止原生和自定义滚动条的旧动画，避免快速筛选后又被旧滚动目标带偏。卡片宽度同时验证了直接放入首页轨道、嵌套在详情相似内容容器内两种布局，避免百分比宽度让外层卡片被原图固有宽度撑开。

媒体卡片宽度受可用空间约束；窄屏的标题、操作区和筛选区可换行。触屏或窄屏直接展示点赞与评论，不要求用户先触发鼠标悬停。键盘聚焦卡片时也显示相同信息，并提供可见焦点样式。

加载状态提示放在 `aria-busy` 容器之外，避免在忙碌状态内被延迟后又随骨架卸载；错误和空结果分别提供适当的状态语义。点赞与评论补充读屏可读的单位文字，装饰图标不参与朗读。骨架轨道不注册自定义滚动条，避免仅用于装饰的加载占位产生额外键盘焦点。

## 7. 验证与当前数据边界

### 当前已知环境情况

本轮检查的真实匿名推荐接口能够成功返回 HTTP 响应，但三个推荐模块的内容列表当前为空。这可以证明当时入口可达且空响应能够被处理，不能据此判断有内容时的排序、封面、旅途匹配已通过真实业务数据验收，也不能仅凭空列表判断底层数据库没有任何内容。可见性、精选标记和旅途聚合条件都可能影响当前匿名结果。

有内容、网络失败、刷新恢复、封面破损及边界日期等场景需要可控数据。浏览器隔离测试使用明确构造的接口响应，后端测试使用隔离数据验证规则。这些测试用于验证指定输入下的实现行为，不能代替真实账号和真实可见内容的业务验收，也不应把测试卡片展示成真实作品。

### 本轮最终验证结果

2026-10-10 最终定向回归：浏览器 60 项通过、21 项按设备/动画模式条件跳过，0 失败；后端 28 项通过、0 跳过；旅途工具单测 5 项通过。浏览器使用与项目匹配的 Playwright Chromium Headless Shell。截图已检查桌面深色与 320px 手机浅色布局。
