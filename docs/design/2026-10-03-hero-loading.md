# 首页全景背景加载优化

## 问题与原因

用户反馈快速切换时偶尔卡顿，图片像隔行扫描一样逐步显现。

首页实际入口是 `FeaturedHero.vue`。原实现有三个相关问题：

- 五张素材都是渐进式 JPEG，高 2160、宽 5092–12963。单张理论 RGBA 解码内存为 42–107 MiB；快速切换会带来较大的下载、解码和绘制开销。
- 首张图直接挂在可见 DOM 上，没有等待完整解码。
- 后续图片用临时 `new Image()` 解码，只缓存成功的 Promise，随后让 Vue 创建另一个图片节点显示。再次选择缓存图时也不重新确认解码状态。浏览器可以回收之前解码的像素，Promise 成功并不意味着图片永久保持可绘制状态。

[HTML 标准的 decode() 说明](https://html.spec.whatwg.org/multipage/embedded-content.html#dom-img-decode)建议将解码完成的同一个图片节点及时插入文档；解码后的像素可用性保证只覆盖紧邻的渲染周期，不是永久缓存保证。

## 实现

- 图片展示状态集中到 `useBackgroundSlideshow.ts`（原 `useHeroSlideshow.ts`，已抽取为可复用模块）。首张和后续图片都在 DOM 外加载，对实际要显示的节点调用 `decode()`，成功后立即插入专用容器。
- 加载/解码期间保持上一张完整画面，标题、编号、选中状态在新图就绪时一起更新。失败或 20 秒超时显示重试，不替换已显示图片。
- 每次选择都有版本编号，过时请求不能更新画面或错误状态；取消未完成的旧图请求。重复的 focus/click 合并，鼠标悬停延迟 90 ms，快速划过的中间项不触发加载。
- 淡入为 240 ms，只同时显示两层完整图片。下一次淡入等待当前过渡结束，再解码并显示最新选择，不反复打断正在绘制的过渡。
- 按最近使用顺序最多保留三个图片节点。缓存图片再次展示前仍调用 `decode()`；过渡结束移除旧的可见层，清理临时 `will-change`。
- 当前画面稳定后延迟 1.2 秒，以低优先级预加载一张邻图。省流量或 2G 网络禁用预加载；切到后台、组件停用或卸载时清理工作。
- 保留鼠标边缘平移、方向键、触摸选择、减少动态效果偏好。尺寸变化时重新选档，旧画面持续可见直至替换完成。

## 资源分档

新增 `scripts/generate-hero-images.mjs`，通过 `npm run images:hero` 生成高 960、1440、1920 的 WebP（quality 86），保持全景宽高比和完整视野，不修改原始 JPEG。每次串行处理一张，避免编码时并发占用大量内存。

按 `max(容器高度, 容器宽度 × 原图高宽比) × min(DPR, 2)` 选择最小够用档位；超出最大档时使用 1920。考虑 cover 的两个方向，不使用会把全景高度压得很小的按宽缩略图。此 DPR 上限控制高密度手机解码成本。

下表为同档五张图片合计；页面不会一次下载所有档位或同时保留五张图片。

| 档位 | 文件体积 | 理论 RGBA 解码内存 | 相对原图 |
| --- | ---: | ---: | --- |
| 原 JPEG，2160 高 | 14,530,160 B | 364.93 MiB | 基准 |
| WebP，960 高 | 3,918,928 B | 72.08 MiB | 传输 −73.0%，像素内存 −80.2% |
| WebP，1440 高 | 8,271,632 B | 162.19 MiB | 传输 −43.1%，像素内存 −55.6% |
| WebP，1920 高 | 13,237,724 B | 288.34 MiB | 传输 −8.9%，像素内存 −21.0% |

这些是资源字节数及 `宽 × 高 × 4` 的像素估算，不代表浏览器进程实测内存或线上 Web Vitals。高分屏仍有大图解码开销，因此完整解码后显示和限制应用缓存仍然必要。

## 验证

- `node --test tests/hero-images.test.mjs tests/panorama.test.mjs`：6 项通过，覆盖高度、DPR、宽屏 cover 选档与原有平移行为。
- `npm run build`：Vue TypeScript 检查及 Vite 生产构建通过。既有地图/视频大 chunk 提示仍存在。
- `PLAYWRIGHT_CHANNEL=chrome` 配合 Playwright：桌面、Pixel 7 和减少动态效果三个项目，共 31 项通过、2 项因设备条件跳过。覆盖首张解码屏障、旧图保持、连续点击与过时响应、缓存图重新解码、失败/超时重试、悬停与键盘、触摸、卸载、后台暂停及单张邻图预加载。
- 真实素材测试通过，核对实际下载档位、全景宽高比、快速切换后唯一有效图片、键盘平移和无横向溢出；桌面与手机截图已目视检查。
- 原始 JPEG 无改动；`git diff --check` 通过。

本机未安装 Playwright 对应版本的 Chromium，验收使用已有 Chrome（配置原本支持该环境变量）。复跑方式：

```powershell
$env:PLAYWRIGHT_CHANNEL = 'chrome'
npm run test:hero
```
